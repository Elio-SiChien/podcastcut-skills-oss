# 播客内容剪辑方法（给 DeepSeek 的说明，也给人看）

来源：本仓库《粗剪》的 6 类删除 + 2026-11-22 一期 62 分钟访谈剪到 40 分钟的实际取舍。

## 先保留，再删
1. **必须保留**：嘉宾的核心观点、具体经历和故事、具体数字、对听众有用的建议；主持人提出主干问题的那句话；串场和换人的过渡句（“那我们进入下一个问题”“你有要补充的吗”这类，删了会跳）。
2. **优先删除**（按这个顺序找）：
   - 录前准备：正式开场白之前的一切（寒暄、设备测试、流程说明、第一次说错重来的开场）
   - 录后闲聊：正式道别之后的一切
   - 制作讨论：录制中讨论剪辑、时长、流程（“没说清楚你们就剪一剪”“我们准备结束吧”）
   - 口误重录：说错名字、重说一遍的前一遍
   - 重复内容：同一个意思讲了两遍以上，留最清楚的一遍
   - 细节展开：和本期主题弱相关的技术细节、数字统计
   - 主持人铺垫过长：主持人复述嘉宾说过的话、讲自己的观点超过 30 秒、问题前后的重复
   - 点名评价其他团队或个人（嘉宾或主持人提到别家同类产品并比较）
3. **保持问答完整**：一个问题删就连回答整段删；不留“问了没答”“答了没问”；不拼出嘉宾没说过的话。
4. **主持人和嘉宾的比例**：同等重要时，先删主持人的话；共同主持人的发言尽量保留（他们本来说得少）。
5. **目标时长是要达到的**：先删确定该删的；不够就按“细节展开 → 主持人铺垫 → 重复内容”的顺序再扫一轮，直到预计时长 ≤ 目标的 98%（还会压停顿、加片头）。

## 输出格式（只返回 JSON）
把整期逐句稿**从头到尾切成连续的块**（每块是一个小话题或一轮问答，通常 20–120 秒；块与块首尾相接、覆盖所有句子、不重叠），给每块打分：
```json
{
  "blocks": [
    {"from": 起始句编号, "to": 结束句编号, "type": "主干|录前准备|录后闲聊|制作讨论|口误重录|重复内容|细节展开|主持人铺垫过长|点名",
     "importance": 1-5, "reason": "一句话：讲了什么、为什么是这个分"}
  ],
  "chapters": [{"from": 编号, "title": "章节标题（10 字以内）"}],
  "notes": "需要人重点听的地方（敏感内容、嘉宾可能不想公开的话）"
}
```
打分标准：5 = 必须保留（核心观点、故事、主干问题）；4 = 重要；3 = 有价值但可删；2 = 弱关联 / 铺垫 / 重复；1 = 应该删。
录前准备、录后闲聊、制作讨论、口误重录一律 1 分。
程序会先删掉 1 分的块，再从低分往高分删，直到达到目标时长；5 分的块永远不删。所以**分数要拉开**，不要都打 4、5 分。
