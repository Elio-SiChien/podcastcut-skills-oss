# Self-iterating product loop

> 2026-06-03 product design discussion between @xiangge-li and podcast-editor-agent.
> Captures the framework for surfacing AI-vs-user diff insights to users without exposing weakness.
> @xiangge-li explicitly asked this be preserved for **product marketing** later — the "AI 在跟你一起学习" angle is a differentiator.

## Why this matters

Most AI tools optimize for "AI gets it right out of the box." When the model is wrong, the user is annoyed and the experience feels broken.

This product flips that — wrongness is a **feature** that powers a tight learning loop:

1. AI proposes edits
2. User accepts / rejects in the cloud-bridge review HTML
3. Every commit auto-runs `eval/compare.js` to quantify the diff
4. **Wins go to the user** (per-episode delivery messaging — "AI 帮你省了 5:42")
5. **Repeat losses go to the agent** (when a detector's retention drops below threshold, agent asks user "want to permanently tune this for your podcast?")
6. User says yes → write to `profile.detector_overrides.json` → next episode behaves better

The user experiences the product **getting smarter every episode**. The agent experiences a real preference signal it can act on. The result is lock-in: every accepted tuning is a personalization the user doesn't want to abandon by switching tools.

## The three messaging tiers

### Tier 1 — Value messaging (every episode, automatic)

Lives in the **每期 delivery chat**. Always present, always positive. No retention numbers, no "AI got X wrong."

```
🎧 成品：<name>.m4a (52.5 min)

AI 帮你做的：
✓ 抓了 112 个衔接片段 = 省 3:08
✓ 抓了 390 个口吃/卡顿 = 省 1:47
✓ 抓了 140 个句首填充词 = 省 44 秒
✓ 抓了 21 个长停顿 = 省 36 秒
你额外加了：29 个整句

这次你接受了我 89% 的删除决策——下次继续这样剪。
```

**Implementation**: `eval/compare.js --format delivery-msg` — generated by Stage 1 PR. Wired into edit-chat 阶段 6.

**Why this works as marketing**: The user sees concrete time saved + an "agreement %" they can brag about ("我家的剪辑师懂我 89%"). The number trends up over time as the detector tuning improves. That trend is the story.

### Tier 2 — Improvement messaging (triggered, opt-in)

**Single-episode trigger**: One detector type has retention < 50% AND N > 10 in this episode → 1 line in chat after delivery:

```
（顺便）这次 in_sentence_repeat 你恢复了 14/15。
你 podcast 的对话节奏里短语重复有时候是强调，不是卡顿。
要不要在这档播客上**永久关掉这个 detector**？「关掉」/「再观察几期」/「忽略」
```

**Multi-episode trigger**: Same detector type has retention < 70% averaged over ≥3 episodes → similar prompt but framed "最近 3 期我注意到 …".

**Framing rules**:
- Position user as the **expert teaching the assistant**, not as the auditor catching AI errors
- "你 podcast 的节奏是 X，我学到了" not "AI 这次错了 N 个"
- Always single-line, easy to dismiss
- Same detector + same user reply → 5-episode cooldown before asking again
- User says "再观察" → defer to multi-episode aggregation

**Implementation**: Stage 2 PR (deferred until 2-3 real episodes of data accumulate, so we set the right thresholds empirically not by gut).

### Tier 3 — Deep retro (on-demand only)

User says "最近怎么样了" / "总结一下" → agent renders a full dashboard from `eval/results.jsonl`. Per-type trend lines, accumulated saved time, top patterns. Markdown table reply.

**Never auto-pushed.** User asks, user gets. No surprise reports.

## What gets persisted and where

Three layers, different scopes:

| Layer | File | Scope | Examples |
|---|---|---|---|
| profile (existing) | `profiles/<name>.json` | per-podcast, stable | name, tone, hosts, glossary, default_aggressiveness |
| detector overrides (Stage 2 add) | `profiles/<name>.detector_overrides.json` | per-podcast, learned | `{"in_sentence_repeat": {"enabled": false, "reason": "ASR 在这档播客上常误判", "applied_at": "..."}}` |
| eval log | `eval/results.jsonl` (line-per-episode) | cross-podcast, audit | `{episode_name, timestamp, per_type: {stutter: {total: 450, tp: 390, fn: 60}}, ...}` |

System-wide changes (e.g. "consecutive_filler threshold should be 4 not 3 universally") never go into per-podcast files. They go into the detector source via PR.

## "Why this won't feel like the AI exposing its own failures"

@xiangge-li's worry: surfacing diff feels like "AI 露短."

The reframe: **Tier 1 talks about wins, Tier 2 talks about learning**. Wrong wording would feel like exposure. Right wording feels like an apprentice asking for feedback.

Key word choices to enforce in chat templates:
- ✓ "你 podcast 的节奏特殊在 X"
- ✓ "我学到了 X"
- ✓ "要不要在这档**永久** tune"
- ✗ "AI 错了"
- ✗ "我误判了 N 个"
- ✗ "这次的 AI 表现"

The product positioning is: **"My editor assistant is learning my style"** — not **"My editor is broken and I have to fix it."**
